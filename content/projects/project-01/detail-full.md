# Dogdream：个人网站搭建过程

## 一、开始

我是一名设计师，工作原因经常需要找一些设计素材，也会顺手打开很多设计师、艺术家或者独立开发者的个人网站。

有些网站做得很好，会让人多看几眼。不是那种作品很多，而是整体的感觉、交互方式或者排版，会让你觉得「这个人真厉害」。

看多了之后，自己也会偶尔想过要不要做一个个人网站。不过因为不会写代码，自己手上的作品也还不太多，觉得好像也没到能认真做一个网站的程度，就一直也没用真正的动手。

后来开始慢慢用一些 AI 工具。像 GPT、Midjourney 这些，其实算是比较早一批在用的。平时会用来做图、写文案、生成一些视频内容。但这些工具一直是分散的，各做各的，没有真正连成一条完整的创作流程。

我一直有一个比较实际的感受是：这些东西是可以串起来的，但我当时做不到。卡点主要还是在代码上。所以「做一个自己的网站」这个想法，一直都在，但也一直没真正开始。

直到后来机缘巧合下有个朋友推荐了 WorkBuddy，是我第一次接触到 Agent 工具。然后就算真正开始做这个网站。

最开始其实没有想「要做成什么样」，更多是先试一下这个工具能不能把想法跑起来。WorkBuddy 很快帮我搭了一个很简单的雏形。能跑起来的时候其实是有一点惊讶和兴奋的——因为之前很多事情在我这里是「做不了」的状态，现在突然变成「可以先出来一个版本」。

但这个状态没有持续两天。WorkBuddy 版本更新之后开始变得不太稳定，速度变慢，生成也经常出问题，整个流程开始变得反复。于是就开始寻找合适的工具。WorkBuddy、VS Code、Cursor、Codex 都用过一段时间，每个工具都有一段时间能用，但都不算稳定。因为有很多很现实的问题，比如 API 地区限制、账号购买、网络不稳定、价格、Agent 的上手难度这些。很多时间其实不是在做设计，而是在「让工具终于能工作」的痛苦中。最终是使用cursor会员，加vscode+api完成了这个网站的搭建。

这个阶段真的很感谢那些愿意解答我的问题的朋友们。

## 二、设计理念

这个网站最开始，其实并没有「走廊」，甚至没有完整结构。只有一个很模糊的画面：一只睡着的狗，一个坐垫，舒服的发梦。

我一直很喜欢那种安静、留白、像凌晨一样的氛围。不想做太强烈的赛博朋克，也不想做特别炫技的科技感——因为梦在我想象里，应该是安静的。

后来，「进入梦里」这个概念开始慢慢往下长。于是开始有了走廊，有了无限向前的空间，有了两侧漂浮的画框。它们不像普通项目入口，更像记忆碎片。每一幅画后面，都是一个过去做过的项目；点击它的时候，进入一个个梦景。


## 三、首页

首页的想法很简单。我喜欢狗，我也养了一条小狗——我想，要不就让他代替我来讲解作品吧，于是就有了首页的画面：全屏白色画布，衬线大写标题「EVERYTHING YOU SEE IS PART OF A DREAM」、梦泡、坐垫，和一只会走过来、躺下、入睡的狗狗。

首页的狗狗，是我遇到的第一个难点。

原本是想做成 3D 模型的。但后来尝试了好几种方法后发现，至少以当前 AI + 我的能力，很难稳定生成真正能用的角色资产，于是最后改成了视频方案。

制作过程大致是这样：

① 先找风格参考。

② 用自己家狗狗的照片配合参考图，在 Gemini 里生成多视图和不同动作。

③ 从里面挑一些状态，去不同的视频生成平台反复测试——即梦、Runway 等视频生成 AI 工具。
最终选定了即梦的首尾帧功能，试了很多版。其实很多视频都很好看，但因为关键词不太准确，且即梦固执地认为狗狗的鼻子应该是黑色的，导致很多好看的动作都无法用上。

④ 视频出来后需要考虑浏览器兼容，就开始处理：剪影剪辑、AE 扣透明底、边缘、压缩、使用 FFmpeg 转 WebM。

⑤ 交给 Agent嵌入网站、调尺寸落点、时序。

## 四、遇到的困难

### 工具与环境

Agent 工具本身就不稳定：WorkBuddy 更新后变慢、生成失败；换 Cursor、Codex 之后，API 地区限制、网络、账号、价格、上手难度，每个都是实际问题。大量时间花在让工具能跑，而不是在做设计。

### 和 AI 协作

AI 很强，但也容易失控。有时候一句话，它会把整个 scene 重构掉；有时候只想改一个按钮，最后连相机系统都一起改坏。后来慢慢建立一些规则：只允许改局部、先规划再执行、不要碰已经确认的结构、修改前先重新读取文件，以及保存 patch 回退点（`backups/checkpoint-*`）。还维护了一份 `DEVELOPMENT_PLAN.md`，把每次决策和失败方案记下来，避免下轮重复踩坑。

### 首页→走廊转场

纯 CSS 白圈 / ring 方案做了很久，始终不可见（白叠白对比不够）。最后改为：捕获首页快照 → Canvas 波纹位移 → 白层覆盖 → 渐隐露出走廊。

### 走廊 3D 与性能

贴图上墙之后曾经明显卡顿，排查后发现是材质重复更新、纹理 needsUpdate 等问题。曾尝试平滑滚轮惯性，但滑动过程掉帧严重，已回退。走廊 Canvas 的 antialias 也经历过开关取舍——不能为了流畅把画质降得太差。

### 移动端与响应式

走廊在移动端踩过很多坑——调响应式时，页面一缩，画框叠在一起、镜头错位，很多参数要分设备单独对，调了很久才稳住。

## 五、使用的工具

| 工具 | 用途 |
|------|------|

## 六、搭建过程

### 第一阶段：WorkBuddy 雏形 → 迁移到 Cursor

WorkBuddy 搭出第一版可跑的页面，走廊交互参考其画廊原型（`scene-gallery.js`）。工具不稳定后，逐步迁移到 Vite + React + Three.js（@react-three/fiber），用 Cursor 持续迭代。

### 第二阶段：首页

见上文第三节。白色画布、标题、梦泡、坐垫、狗狗视频三部曲；标题定稿；响应式断点。

### 第三阶段：梦境走廊

一字型封闭白灰 3D 空间，滚轮推动相机前进，左右各 6 个画框、共 12 个。已完成：琉璃材质画框、海报光照与阴影、地板烟雾、流光与光粒、狗脚印轨迹、画框点击聚焦。

### 第四阶段：页面串联

涟漪转场、三级项目详情页（ProjectDream）、聚焦页「进入深梦」与「wake up」返回首页的完整链路。

### 进行中

- 聚焦页视觉升级（灯光、墙签式说明、海报交互等）
- 12 个画框位填入真实项目（第一个即本文）
- Netlify 部署上线
